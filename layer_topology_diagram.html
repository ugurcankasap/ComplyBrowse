3-Layer Verification Architecture

Decision Precedence Topology — L1/L2/L3 Decision Flow

L1 — Managed Policy

Registry / GPO / MDM / policies.json. Not user-editable, and enforced by the browser. If present, it always has the highest priority.

L2 — User Setting

Preferences / prefs.js. User-revertible. Considered only when L1 cannot produce a result (ABSENT/NOT_APPLICABLE/NOT_ASSESSED).

L3 — Runtime Arbiter

Command-line flags of the running process. Triggered only when L1=COMPLIANT conflicts with L2=NON_COMPLIANT. It can never turn a FAIL into PASS.

Decision Matrix — Which Layer Overrides Which?

L1 State Is L2 Effective? Is L3 Effective? Possible Outcome Counted in Score?
COMPLIANT (no conflict) No No PASS (L1) Yes
COMPLIANT + L2 conflict Trigger Yes (arbiter) PASS (L1) / FAIL (L3) Yes
NON_COMPLIANT_VALUE No — not evaluated No FAIL (L1) — definitive Yes
ABSENT / NOT_APPLICABLE / NOT_ASSESSED Yes, can decide No PASS_NOT_ENFORCED (L2) / FAIL (L1 veya L2) / NOT_ASSESSED Depends on state

Critical point: when L1=NON_COMPLIANT_VALUE, L2 becomes irrelevant — real browser behavior is driven by the enforced (incorrect) policy, and local user settings are ignored. L3 can never convert a FAIL into PASS; it can only reveal that an apparent PASS was neutralized at runtime.
